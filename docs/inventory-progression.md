# アイテム・装備・成長

[README](../README.md) / [レビュー](../checklists/review.md)

根拠: [XAG 109・112・115](sources.md)。能力差分や振り直しの提案は本ガイドの応用です。

## INV-01 — SHOULD / P1: 持ち物は用途と対象から探せるようにする

- **理由:** 名前を覚えていなくても必要な道具へ到達できる。
- **推奨:** 回復・戦闘・素材などの分類、数量、使用対象を示す。並べ替えの状態を明示し、使った後も一覧位置を保つ。
- **悪い例:** 同じ瓶の絵だけが並び、数量は選ぶまで不明。
- **良い例:** 「澄んだ薬 ×4 / 味方1人の毒を解除」。使用不可なら「毒の仲間がいません」。
- **例外・トレードオフ:** 小規模な一覧ではタブを増やしすぎない。分類で見失う場合は全件表示も残す。
- **確認:** 名前を指定せず「毒を治して」と依頼し、探索・使用・取り消しを観察する。

## INV-02 — SHOULD / P1: 装備比較は損益と特殊効果を併記する

- **理由:** 単一の攻撃力や色だけでは役割に合う選択ができない。
- **推奨:** 装備する人物、現在→変更後の値と符号付き差分、失う耐性・得る効果、装備条件を同時表示する。
- **悪い例:** 「強い装備」とだけ表示し、速度低下や毒耐性喪失を隠す。
- **良い例:** 「防御 18 → 23（+5） / 速度 12 → 9（−3） / 毒耐性: 失う」。
- **例外・トレードオフ:** 未発見の効果は伏せられる。自動最強装備を用意するなら評価軸と手動変更を提供する。
- **確認:** 攻撃以外を重視する課題でも、変更前に利点・欠点を説明できるか聞く。

## INV-03 — MUST / P0: 売却・破棄・合成の不可逆損失を守る

- **理由:** 一括操作で希少品や必要素材を失う事故を防ぐ。
- **推奨:** 数量・合計・消える対象を確定前に表示し、希少品のロックや買い戻しを検討する。取り消せない場合はその旨を明記する。
- **悪い例:** 「整理する」で装備中の唯一品まで売却する。
- **良い例:** 「星の指輪を売る / 装備中: セナ / 買い戻せません」「戻る／売却する」。
- **例外・トレードオフ:** 日常の安価な売買には確認を乱発せず、取り消し可能な設計を優先。警告の対象条件は一貫させる。
- **確認:** 最大数量、一括対象、装備中、ロック中、購入後の所持金を確認する。

## PRG-01 — SHOULD / P1: 成長の現在地と選択の結果をつなぐ

- **理由:** 経験値や能力名だけでは、何ができるようになるか判断しにくい。
- **推奨:** 現在能力、次の解放条件、未使用ポイント、選択による効果を表示し、数値と説明の用語を統一する。
- **悪い例:** 「精神+1」。その能力が回復量に影響することは別画面の奥にだけある。
- **良い例:** 「集中: 回復術の効果が上がる / 次の習得: 静かな灯 / 必要ポイント2」。
- **例外・トレードオフ:** 全成長先の開示がネタバレになるなら範囲を制限する。ただし現在使うポイントと戻せるかは明示。
- **確認:** 選択前に変化・条件・振り直し可否を説明してもらい、表示値と適用後の値を照合する。

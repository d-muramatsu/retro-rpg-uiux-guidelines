# 情報階層・メニュー・操作

[README](../README.md) / [レビュー](../checklists/review.md)

根拠: [XAG 112・107・115](sources.md)。情報の段階化と具体的なフォーカス規則は本ガイドの設計提案です。

## NAV-01 — SHOULD / P1: いまの判断に必要な情報を同じ画面に置く

- **理由:** 複数画面の数値を覚えて比較する負担を減らす。
- **推奨:** 画面名→現在の対象→選択肢→変化・消費→操作案内の順に整理し、詳細説明は呼び出せるようにする。
- **悪い例:** 装備画面に現在能力がなく、閉じてステータス画面へ移動する。
- **良い例:** 「装備先: ミナ / 防御 18 → 23（+5） / 詳細」。フレーバー文は詳細に分ける。
- **例外・トレードオフ:** 図鑑の閲覧は情報量が主役。隠し効果を表示する必要はないが「未解明」と既知の効果を区別する。
- **確認:** 画面間を往復せずに購入・装備の理由を説明できるか観察する。

## NAV-02 — MUST / P0: 決定・戻る・フォーカスの意味を揃える

- **理由:** 操作の取り違えと抜け出せない画面を防ぐ。
- **推奨:** 決定で次の段階へ、戻るで一段前へ。モーダル中は背面に入力を通さず、閉じたら起点にフォーカスを戻す。開閉に使った押下を次画面へ持ち越さない。
- **悪い例:** 戻るで購入が確定する。警告を開いたキーの連打で同意まで通る。
- **良い例:** 「品物 → 数量 → 合計確認 → 購入」。戻ると数量と一覧位置を保って戻る。
- **例外・トレードオフ:** 未保存編集を破棄するときだけ、失う変更を示す確認を挟む。一般の閲覧終了には不要。
- **確認:** 全画面をマウスなしで出入りする。モーダル、長押し、連打、機器切断後も誤確定しないか試す。

## NAV-03 — SHOULD / P1: 一覧の位置と使えない理由を見失わせない

- **理由:** 無反応の項目や意図しない移動は、ルールの推測を強いる。
- **推奨:** 選択枠＋名称で現在地を示す。無効項目でも説明に到達できるようにし、理由と回復条件を表示。並べ替え後は対象IDを維持し、消滅時は近傍へ移す。
- **悪い例:** 灰色の「復活」が押せないだけ。売却のたび先頭に戻る。
- **良い例:** 「復活: 戦闘不能の仲間がいません」。選択枠は静止して識別可能。
- **例外・トレードオフ:** 1次元一覧の端の循環は有用だが、格子を予想外に折り返さない。無効項目を飛ばす設計なら別の説明経路が必要。
- **確認:** 空一覧、最終行削除、長い一覧、格子の端、無効状態を機器ごとに試す。

## NAV-04 — MAY / P2: よく使う操作を短縮する

- **理由:** 判断を伴わない反復を減らし、テンポを保つ。
- **推奨:** 最近の選択、並べ替え、お気に入り、数量変更を用意し、現在の選択状態を見えるようにする。
- **悪い例:** 前回の「全て売る」が説明なしで初期選択される。
- **良い例:** 通常コマンドは記憶するが、希少品の売却確認は安全な「戻る」から始める。
- **例外・トレードオフ:** 記憶が予想外の行動を生む場面では固定初期値を選ぶ。ショートカット専用機能は作らない。
- **確認:** 初回と再訪を比較し、短縮操作による誤選択が増えていないか観察する。

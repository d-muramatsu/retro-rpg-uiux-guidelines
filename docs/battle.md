# 戦闘: 判断から結果まで

[README](../README.md) / [レビュー](../checklists/review.md)

根拠: [XAG 103・109・112・116](sources.md)の情報伝達・時間・操作原則。戦闘の具体的な予告、消費時点、順序表示は本ガイド独自の提案です。

```text
行動者 → コマンド → 技・道具 → 対象・予測 → 確定 → 解決 → 結果確認
             ←──── 戻る: 資源を消費しない ────┘
```

## BAT-01 — MUST / P0: 対象とコストを確定前に理解できる

- **理由:** 誤った相手への使用や意図しない希少資源の消費を防ぐ。
- **推奨:** 行動者、単体／範囲、味方／敵、消費と残量、使用条件を対象選択中に表示する。キャンセルは無消費。実際にいつ消費するかを統一する。
- **悪い例:** 技名を選んだ瞬間にMPが減り、全体技か単体技かは演出まで分からない。
- **良い例:** 「灯火 / 味方1人 / MP 4（現在11 → 7） / HP回復」。対象に名前と枠を付ける。
- **例外・トレードオフ:** 予約時消費が独自ルールなら確定境界を示す。通常行動に毎回余分な確認ダイアログは要らない。
- **確認:** キャンセル前後の資源、誤対象、対象不在、重複入力での二重消費を検証する。

## BAT-02 — SHOULD / P1: 予測と確定結果を区別する

- **理由:** 外れや変動が表示の嘘に見えないようにする。
- **推奨:** 既知の属性・状態異常・持続と効果を示し、ダメージ幅や命中率が変動するなら予測と明記。解決後に成功・無効・回避・耐性の差を伝える。
- **悪い例:** 「100ダメージ」と予告して外れても無言。
- **良い例:** 「予測 24〜32 / 命中は保証されない」「石の兵: 耐性により眠らなかった」。数値はこの架空技の例であり基準ではない。
- **例外・トレードオフ:** 敵情報の発見が遊びなら未知は「不明」。正確な内部式を公開する必要はない。
- **確認:** 同じ技を通常・耐性・無効・回避条件で試し、結果の理由が分かるか観察する。

## BAT-03 — SHOULD / P1: 時間と行動順の規則を説明する

- **理由:** 待てる場面と時間が進む場面の誤解を防ぐ。
- **推奨:** ラウンド制なら入力・解決段階、行動順制なら次の行動者と変化予告を示す。速度変化は確定／暫定を区別する。
- **悪い例:** 説明文を読んでいる間にも敵が動くが表示は「選択中」のみ。
- **良い例:** 「入力中: 時間停止」「加速後の順序（予測）: ミナ → 番人 → セナ」。
- **例外・トレードオフ:** 順序非公開の駆け引きは成立するが、公開範囲を一貫させる。ATB・アクションは[拡張](extensions.md)を参照。
- **確認:** 防御・遅延・加速・割り込みで表示と結果を照合。プレイヤーが現在の段階を説明できるか聞く。

## BAT-04 — MUST / P0: 重要な状態変化を演出だけにしない

- **理由:** 速い演出、色、音だけでは戦術判断に必要な結果を見落とす。
- **推奨:** HP、戦闘不能、行動不能、付与／解除を文字と識別可能な記号で残す。結果ログで読み直せ、演出短縮時も更新を保つ。
- **悪い例:** 毒は緑色になるだけ。高速化すると何が解除されたか分からない。
- **良い例:** 「毒: 行動終了時にHP減少 / 残り2回」。残回数の減るタイミングもヘルプに示す。
- **例外・トレードオフ:** 同時効果はまとめてもよいが、結果と対象を追跡可能にする。全てを画面中央へ重ねない。
- **確認:** 音なし・色識別に頼らない表示・演出短縮で勝敗に関わる結果を追えるか確認する。

# セーブ・中断・再開・不可逆な選択

[README](../README.md) / [レビュー](../checklists/review.md)

根拠: [XAG 108・109・115](sources.md)。保存処理の状態表と復旧方法は本ガイドの提案です。

## SAV-01 — MUST / P0: 保存の開始・成功・失敗を区別する

- **理由:** 保存済みという誤認による進行喪失を防ぐ。
- **推奨:** 「保存中」「保存しました」「保存できませんでした」を分ける。成功確認前に完了扱いしない。失敗時は再試行と安全な戻り先を示し、既存データを保護する。
- **悪い例:** ボタン押下で即座に「完了」、書込み失敗しても無言。
- **良い例:** 「保存できませんでした。空き容量を確認して再試行してください。前の保存データは変更していません」（最後の文は実装上保証できる場合のみ）。
- **例外・トレードオフ:** 自動保存の表示は簡潔でよい。保存を伴う終了は完了／失敗が分かるまで別扱いにする。
- **確認:** テスト環境で容量不足・書込み失敗・中断を再現し、復元データとUIの説明を照合する。

## SAV-02 — SHOULD / P1: 再開地点を識別でき、長い進行喪失を避ける

- **理由:** 異なるスロットや自動保存を取り違えず、中断しやすくする。
- **推奨:** 手動と自動の区別、保存日時、場所、進行要約を表示する。自動保存と手動保存を分け、重要分岐前の記録を保つ設計を検討する。
- **悪い例:** 「データ1」だけが並び、全自動保存が唯一の手動スロットを上書きする。
- **良い例:** 「手動2 / 水門前 / 保存日時… / 目的: 門の仕掛けを調べる」。
- **例外・トレードオフ:** セーブ地点制・一命制でも、開始前に復帰・喪失の範囲を説明し、中断専用保存を検討する。保存頻度は固定の普遍値にしない。
- **確認:** 手動保存→自動保存→終了→ロード、別スロット上書き、古いデータ読み込みを試す。

## SAV-03 — MUST / P0: 不可逆な選択は失う範囲を伝える

- **理由:** 展開の驚きと、操作仕様の不意打ちを区別する。
- **推奨:** 何が戻せないか、保存へどう影響するかを確定前に示す。具体的な行動名をボタンにし、安全な戻り先を初期選択する。
- **悪い例:** 「よろしいですか？ はい／いいえ」だけで仲間と持ち物が永久に消える。
- **良い例:** 「この門を閉じると、この章では町に戻れません。今の手動保存は残ります。戻る／門を閉じる」。
- **例外・トレードオフ:** 物語の結果そのものは隠せる。「この選択は後で変更できません」のように操作上の不可逆性だけ伝える方法もある。
- **確認:** 文面から喪失範囲を説明できるか聞き、戻る・連打・再ロードで説明と一致するか試す。

## SAV-04 — MUST / P0: 遷移後の状態と入力の扱いを決める

- **理由:** 全滅後・ロード後・画面切替中の曖昧さは進行不能や二重操作につながる。
- **推奨:** 次のような状態表を実装担当と共有し、確定前後を区別する。
- **悪い例:** 「再挑戦」で消費アイテムだけが失われ、敵は全回復するが説明がない。
- **良い例:** 「戦闘直前から再挑戦（戦闘中の消費は戻ります）」と実際の復元状態を揃える。
- **例外・トレードオフ:** 敗北ペナルティを残す設計でも、その範囲を事前に示す。アプリの強制終了からの復帰保証範囲も決める。
- **確認:** 各遷移の前後で所持品・HP・目的・位置・フォーカスを照合する。

| 起点 | 操作 | 遷移先 | 設計時に決めること |
| --- | --- | --- | --- |
| プレイ中 | 保存 | 保存中→成功／失敗 | 入力抑止、失敗時の復帰、既存データ保護 |
| 戦闘終了 | 敗北 | 再挑戦／ロード選択 | 資源、経験値、地点、敵状態の復元範囲 |
| プレイ中 | ロード | 未保存進行の確認→読み込み | 失う進行、キャンセル、失敗時の状態 |
| 読み込み中 | 完了 | 再開地点 | 入力持越し防止、設定と目的表示 |

# 原則と優先度

[README](../README.md) / [レビュー](../checklists/review.md)

## 判断の基準

レトロらしさは、ピクセルアート、限られた配色、窓枠、短い効果音、間の取り方で表現できます。読めない文字、無説明の消失、同じ操作の反復を必須の様式にしません。難しさを残す場合も、何を判断するゲームなのかを設計書に書きます。

| 表記 | 本資料での意味 | レビューでの扱い |
| --- | --- | --- |
| MUST / P0 | 進行不能・重大な誤操作・情報欠落を防ぐ最低条件 | 未解決なら対象機能の公開を止める。適用外は理由と代替策を記録 |
| SHOULD / P1 | 通常は採用する推奨 | 不採用理由、代替策、観察結果を記録 |
| MAY / P2 | 作風・機種・遊び方による選択 | 仮説を決めて比較検証 |

これは編集上の優先度であり、外部標準の MUST/SHOULD の転記ではありません。P0だけの達成を「アクセシビリティ対応完了」と呼ばないでください。

## ルールの読み方

各ルールにはID、優先度、理由、推奨パターン、悪い例／良い例、例外・トレードオフ、確認方法を記載します。悪い例も良い例も架空のものです。根拠欄のXAG番号は関連原則を指し、RPG固有の文言やUI配置をそのまま要求しているわけではありません。[出典と対応関係](sources.md)を参照してください。

## 導入時に記録すること

- 対象: 入力機器、画面・視距離、言語、出力解像度、内部描画解像度、UI拡大方式。
- 判断モデル: ラウンド制／行動順制／ATB、確定・取り消しの境界、隠す情報と理由。
- 保存モデル: 手動、自動、中断保存、敗北後復帰、複数スロット、破損時対応。
- 情報モデル: 常時表示、選択時に表示、詳細で表示。未知情報の公開タイミング。
- 支援: 読みやすい文字、再割り当て、読み上げ、字幕、演出軽減、ヒントの提供範囲。

普遍的な「選択肢は必ず3個」「文字は16px」を設けません。候補の意味・利用頻度・表示環境とテスト結果で決めます。内部フレームバッファの1px、最終出力の1px、CSSの1pxは同一ではありません。
